# 仕様書: M5Stack Basic GPS位置情報 APRS送受信機 (1200bps AFSK)

最終更新: 2026-11-17 (0.14.0)。版ごとの変更はリポジトリの `CHANGELOG.md` にまとめている。
「[未定]」は未決定、「(仮)」は実機で調整する前提の仮の値、「[案]」は提案段階の内容。

## 1. 目的
M5StackでGPS位置情報をAPRSパケットにして、1200bps AFSKで無線機のマイク端子へ出力する。
無線機のイヤホン端子から受信したAFSKをデコードし、画面に表示する。

## 2. ハードウェア・接続
- 本体: M5Stack Basic V2.6 (ESP32、LCD、ボタンA/B/C、内蔵スピーカー)
- GPS: M5Stack用GPSモジュール V2.1 (ATGM336H / AT6668)
  - NMEA0183。UART2、115200bps、8N1、RX=GPIO16、TX=GPIO17
  - 動作実績のある初期化: `GPSSerial.begin(115200, SERIAL_8N1, 16, 17);`
- 無線機: ICOM ID-31 (データ端子なし)。アナログFMで運用し、D-STARのDVモードは使わない
- 想定運用周波数: 431.04MHz (430MHz帯の1200bps AFSK用)。無線機側で設定する。ソフトの仕様には影響しない
- 送信: DAC出力(GPIO26、チャンネル2) → 無線機のマイク端子
- 送信音のモニター: DAC出力(GPIO25、チャンネル1。内蔵スピーカーにつながっている)。送信と同じ波形を、音量を絞って出す(4.3)
- 受信: 無線機のイヤホン端子 → ADC入力(GPIO36、ADC1_CH0、入力専用)
- 記録: M5Stack Basic内蔵のmicroSDスロット(SPI、CS=GPIO4。LCDとSPIバスを共有)
- 入力回路(レベル調整・直流バイアス・過大入力の保護)と、出力の減衰は、外部で別途設計済みとする(ソフトの対象外)。ADCに入る信号は、約1.65Vの直流バイアスに、ADCの範囲内の振幅が乗る前提
- PTT: ソフトが制御する(GPIO5。4.3)。GPIO5 → (ダイオードまたは発光ダイオード+抵抗1〜2.2kΩ) → NPNトランジスタ 2SC1815 のベース(ベース-GND間に10kΩ)。コレクタは抵抗を介して無線機のマイク線へ、エミッタはGNDへ。無線機のPTT線へGPIOを直結しない。ソフトは、起動時と終了時に必ずPTTをオフにする
- キーボード(任意): M5Stack CardKB2 (または CardKB)。本体のGroveポートA(I2C、GPIO21/22、アドレス0x5F)につなぐ。本体内部のI2Cと同じ線なので、M5Unified の M5.In_I2C で読む
- M5UnifiedのスピーカーとマイクはOFFにして初期化する(`internal_spk=false`、`internal_mic=false`)。DACを取り合わないため

## 3. 設定 (config.txt と fw_config.h)
### 3.1 microSD の設定ファイル /aprs/config.txt (局ごとの設定)
- 局ごとに変える設定と、無線機・基板に合わせて調整する値は、microSD の `/aprs/config.txt` に書く(`app_config.h` / `app_config.cpp`)。ビルドのときに書き換えるファイルはない(同じファームウェアを誰でも使える)
- 書き方: 1行に1つ `キー = 値`(UTF-8)。行の先頭(空白の後を含む)が `#` の行はコメント。空行は無視。値の途中の `#` は文字として扱う。キーは大文字小文字を区別しない。値の前後の空白は取り除く。UTF-8 の BOM と CRLF の改行も読める。ファイルは6KBまで(0.13.1 までは4KB。見本は約3KB)
- 項目(書かなかった項目は初期値):

| キー | 内容 | 初期値 |
|---|---|---|
| callsign | 自局のコールサイン(英数字6文字まで、数字を含む。SSIDは書かない。SSIDは設定メニュー) | NOCALL(未設定。送信しない) |
| comment | 位置に付けるコメント(表示できるASCII、43文字まで。`\|` `~` は不可) | M5Stack |
| fixed1〜8 | 固定位置 `名前, 緯度, 経度[, 高度m]`(名前は半角9文字まで。空で未設定) | 未設定(名前 Home、Spot2〜8) |
| digipath1〜3 | デジパスの候補(空 = なし。`WIDE1-1,WIDE2-1` のように8個まで。空白は取り除く) | なし / WIDE1-1 / WIDE1-1,WIDE2-1 |
| msg1〜8 | メッセージの定型文(ASCII、67文字まで。`\|` `~` `{` は不可)。1つでも書けば、書いたものだけを使う(空の欄は詰める) | QSL, 73, TNX, QRV, QRT, OK, On my way, Arrived |
| friend1〜8 | よく交信する局(宛先の候補。SSID付きでもよい)。書き方は msg と同じ | なし |
| tx_amp_mark / tx_amp_space | 送信トーンの振幅(1〜127) | 100 / 55(IF v1 基板で確認) |
| ptt_on_delay / ptt_off_delay | PTTを入れてから音を出すまで(0〜2000ms) / 音の後PTTを切るまで(0〜1000ms) | 300 / 50 |
| ptt_active_high | 1: HIGHでPTTオン、0: LOWでオン | 1 |
| tx_preamble | パケットの先頭のフラグの数(1〜255) | 60 |
| flex_low_speed / flex_high_speed | フレックス(4.3.3)の遅いとき・速いときの速度(2〜30 / 2〜90 km/h。low < high) | なし(見本に 5 / 70) |
| flex_slow_rate / flex_fast_rate | フレックスの遅いとき・速いときの間隔(1〜100分 / 10〜180秒) | なし(見本に 30 / 120) |
| flex_turn_angle / flex_turn_slope / flex_turn_time | フレックスの曲がりの最小角(5〜90度)、傾き(1〜255。10度×km/h 単位)、送信の最短間隔(5〜180秒) | なし(見本に 28 / 26 / 30) |
| flex_slow_dist | フレックスで遅いときでも、前回送った位置からこの距離動いたら送る(0〜5000m。0=使わない。独自の追加) | 0 |

- フレックスの値には初期値がない(見本のファイルにだけ書いてある。値は八重洲・ケンウッドの初期値)。flex_slow_dist 以外の7つがそろっていない(または low ≧ high)と、フレックスは選べない。0.11.0 以前の config.txt には無いので、使うときは書き足す

- 書き間違い(`=` がない、知らない項目、値が範囲外・使えない文字・形が違う、長すぎる)のある行は無視して、その項目は初期値のまま。行番号と内容を記録する(8件まで。件数はすべて数える)
- 起動時に1回だけ読む。書き換えたら再起動する
  - ファイルを読めたら、その中身を本体の不揮発領域に控えとして保存する(中身が変わったときだけ)
  - SDが無い・読めないときは、控え(前回読めた中身)を使う。控えも無ければ初期値
  - SDはあるがファイルが無いときは、控えがあれば控えを、無ければ見本(初期値と説明のコメント入り)を `config.txt` として書き出す
  - 4KBより大きいファイルは読まない(控えを使い、画面に知らせる)
- 起動時に、書き間違い(最初の1件と件数)、見本の書き出し、控えでの動作を画面に10秒出す。シリアルの診断出力には `CFG source=... errors=...` と書き間違いをすべて出す。動作ログにも読み込みの結果を残す
- コールサインが未設定(NOCALL)のときは、位置・メッセージ・Ackを送信しない(自局画面に「コールサイン未設定 (config.txt)」。A長押しでは「コールサイン未設定のため送信しません」)。受信はする
- 設定メニューのバージョン情報に、読み込みの結果(config.txt / 本体の控え / 初期値)と、書き間違いの件数・最初の1件を出す

### 3.2 ファームウェアに固定の設定 fw_config.h
- ピン、AFSKの値、バッファの大きさ・件数、待ち時間、メニューの値の初期値などは `fw_config.h` に置く(0.8.0 までの `config.h` は使わない)
- 他のコードに、これらの値を直接書かない
- `fw_config.h` の主な内容:
  - APRS: APRS_DTI、DEST_CALLSIGN、DEST_SSID
  - 曖昧化: DEFAULT_AMBIGUITY_LEVEL、MAX_AMBIGUITY_LEVEL
  - 送信オプション: DEFAULT_SEND_COURSE_SPEED、DEFAULT_SEND_ALTITUDE
  - デジパス: DIGIPATH_CHOICE_COUNT、DEFAULT_DIGIPATH_INDEX(候補の中身は config.txt)
  - シンボル・SSID の初期値: DEFAULT_SYMBOL(`"/>"`)、DEFAULT_SSID(9)。選べるシンボルの表は `symbols.cpp` の SYMBOL_CHOICES(4.5.4)
  - 保存: NVS_NAMESPACE
  - ピン: GPS_BAUD、GPS_RX_PIN、GPS_TX_PIN、AFSK_TX_DAC_PIN(26)、AFSK_TX_MONITOR_PIN(25。0でモニターなし)、AFSK_RX_ADC_PIN、SD_CS_PIN
  - PTT: PTT_PIN(5。-1でPTT出力なし)、PTT_MAX_ON_MS(10000)、CALIB_MAX_ON_MS(30000。調整トーンの最長時間)。極性と待ち時間は config.txt
  - 診断出力: DIAG_SERIAL(1)、DIAG_STATUS_INTERVAL_MS(5000)
  - モニター音量: MONITOR_LEVEL_MAX(4)、DEFAULT_MONITOR_LEVEL(2)、MONITOR_SCALE_TABLE
  - 位置の取得元: POSITION_SOURCE_GPS/LAST/FIXED、DEFAULT_POSITION_SOURCE、FIXED_POSITION_COUNT(8)、DEFAULT_FIXED_INDEX、LAST_POS_SAVE_DISTANCE_M(500)、LAST_POS_SAVE_INTERVAL_SEC(600)
  - メッセージ: MSG_PRESET_MAX(8)、MSG_FRIEND_MAX(8)(中身は config.txt)
  - GPS途絶: GPS_LAST_FIX_VALID_SEC、GPS_NO_DATA_TIMEOUT_MS
  - 受信一覧・ログ: RX_LIST_COUNT、LOG_DIR
  - 受信の復調・状態表示: RX_TONE_LEVEL_INIT、RX_DATA_SYNC_FLAGS(3)、RX_RESULT_SHOW_MS(2000)
  - 受信バッファ: RX_RINGBUF_MS、RX_PACKET_QUEUE_COUNT
  - AFSK: AFSK_BAUD、AFSK_MARK_HZ、AFSK_SPACE_HZ、TX_SAMPLE_RATE_HZ、RX_SAMPLE_RATE_HZ、TX_TAIL_FLAGS(プリアンブルと振幅は config.txt)
  - ボタン: LONG_PRESS_MS
- 新しい定数が必要な場合は、コード側で仮定せず、追加する定数名を提案として示す

## 4. 機能要件
### 4.1 GPS取得
- NMEAから、緯度・経度・測位状態・時刻・日付を取得する。使うNMEA文は RMC と GGA (位置・時刻・日付・測位状態・速度・方位はRMC、高度はGGA)。日時は測位前(ステータスV)のRMCでも、日付があり年が2024〜2079年なら使う(時刻合わせ前の既定の日付を除く)
  - センテンス名の先頭の2文字(GN、GPなど)は見ず、`RMC` と `GGA` の部分で判別する
  - 末尾のチェックサムが合わないセンテンスは破棄する
  - RMCの測位状態が無効(`V`)のときは、位置を更新しない
  - GGAは、高度の送信がオンのときに使う
- 最終測位位置の扱い:
  - 測位が得られているときは、最新の測位位置を使う
  - 測位が失われても、最終測位から GPS_LAST_FIX_VALID_SEC (300秒=5分) の間は、最終測位位置を使って送信できる
  - 5分を超えたら未測位とみなし、パケットを送出しない。画面に警告を表示する
  - 起動後に一度も測位していない場合も、未測位として送信しない
- NMEAが GPS_NO_DATA_TIMEOUT_MS 以上届かないときは、GPSを受信できていないことを画面に表示する(「測位なし」とは区別する)
- 最終測位位置が古い間(測位が失われている間)は、進行方向・速度は送信に付けない [案]

### 4.1.1 位置の取得元(自局の位置)
自局の位置(送信する位置、画面の表示、受信一覧の距離・方位)は、設定メニューの「位置の取得元」で選んだものを使う。**自動では切り替えない**(誤った位置を送らないため)。
| 取得元 | 内容 |
|---|---|
| GPS (初期値) | 4.1の動作。現在のGPSの位置(最終測位から5分以内) |
| 最後の位置 | 最後に保存した位置(不揮発領域) |
| 固定位置 | config.txt の fixed1〜8 から選んだ位置(最大8件。緯度・経度が両方0の欄は「未設定」として扱い、メニューにも出さない) |
- 選んだ取得元の位置が使えないときは、送信しない。画面に理由を出す(GPS: 受信なし/測位待ち、保存位置なし、固定位置が未設定)。他の取得元へ自動で切り替えることはしない
- 進行方向・速度は、取得元がGPSのときだけ送る。高度は、取得元が持っている場合(GPS、または固定位置に高度を書いた場合)だけ送る
- 自局画面に、GPS以外の取得元のときは「位置:保存位置」「位置:固定 名前」と目立つ色で表示する。GPSが使えず取得元がGPSのままのときは、設定の位置の取得元を変えられることを案内する
- 「最後の位置」の保存:
  - 現在のGPS測位があるときだけ保存する。最初の測位で1回保存する(前回の保存位置から50m以内なら書かない)
  - その後は、前回の保存位置から LAST_POS_SAVE_DISTANCE_M (500m) 以上動き、かつ LAST_POS_SAVE_INTERVAL_SEC (600秒) 以上たったときに保存する
  - 送信中と信号の受信中は書き込まない。書けなかったときは10秒後に再試行する
  - 不揮発領域には26バイトのデータ(バージョン1)として保存する
- 取得元が変わったら、動作ログに `pos_source` を記録する

### 4.2 パケット生成(送信は非圧縮形式の位置レポート)
- 仕様: APRS101。AX.25 UIフレーム(制御0x03、PID 0xF0)
- 送信元: MY_CALLSIGN-(設定のSSID。SSIDが0のときは付けない)
- 宛先: DEST_CALLSIGN-DEST_SSID。TOCALL は `APM5AP`(aprs-deviceid で M5APRS に割り当て済み、2026-11。0.13.3 までは汎用の `APRS`)。ビーコンもメッセージも同じ
- デジパス: 選択中の候補(なし / WIDE1-1 / WIDE1-1,WIDE2-1)
- 情報フィールド: `=`(メッセージ機能あり。APRS_DTI) + 緯度 `DDMM.mmN/S` + シンボルテーブルID + 経度 `DDDMM.mmE/W` + シンボルコード + コメント
  - シンボルは設定で選んだもの。コメントは APRS_COMMENT (最大43文字)
  - 進行方向・速度・高度の送信は、設定メニューでオンオフできる。初期値はすべてオフ(DEFAULT_SEND_COURSE_SPEED、DEFAULT_SEND_ALTITUDE)
  - メニュー項目は「進行方向・速度」(まとめて1項目)と「高度」の2つ
  - 進行方向・速度がオンのとき: シンボルコードの直後に `CSE/SPD` (進行方向3桁(度)/速度3桁(ノット))を付ける。値はRMCから得る
  - 高度がオンのとき: コメントの前に `/A=aaaaaa` (フィート、6桁)を付ける。高度はGGAの値(メートル)をフィートに換算する
  - 進行方向・速度を付けた場合、コメントは最大36文字 (APRS101)
- 位置情報の曖昧化(レベル0〜4)
  - レベルに応じて、緯度経度の下位の桁をスペースに置き換える(1=分の小数第1位、2=分の1の位、3=分の10の位、4=度の位まで)
  - 同じレベルを、緯度と経度の両方に適用する

### 4.3 AFSK送信 (Bell 202)
- 1200bps、MARK=1200Hz、SPACE=2200Hz、位相連続
- NRZI符号化(0でトーン反転)、ビットスタッフィング(1が5つ続いたら0を挿入)、HDLCフラグ0x7E、FCS=CRC-16-CCITT、各バイトはLSBから送出
- 送出順: プリアンブル(TX_PREAMBLE_FLAGS個のフラグ) → フレーム → FCS → TX_TAIL_FLAGS個のフラグ
- DACのサンプリングは TX_SAMPLE_RATE_HZ。トーンの振幅は TX_AMP_MARK / TX_AMP_SPACE で別々に設定する(マイク経路のプリエンファシスで2200Hzが強くなるため)
- 送出のきっかけ: 通常画面でボタンAを長押ししたとき(長押しの時間に達した時点)、1パケットのみ。手動の送信は他局の送信を待たない(ユーザーの判断)。ほかに、自動送信(4.3.3)
- 送信中は受信を止める
- 出力ピン: 無線機へは AFSK_TX_DAC_PIN (GPIO26)。モニター用に AFSK_TX_MONITOR_PIN (GPIO25) へ同じ波形を音量を絞って出す(割り込みの中で、2つのDACに続けて書く)
- モニター音量: 5段階(0=ミュート〜4=最大)。設定メニューの「モニター音量」で選び、不揮発領域に保存する。波形に MONITOR_SCALE_TABLE の係数(256=無線機側と同じ大きさ)を掛ける。ミュートのときはモニター側のDACを動かさない。段階を変えるときの試験音は出さない。送信中に音量を変えても反映は次の送信から
- PTT制御(PTT_PIN。常に自動。設定で切り替えない):
  1. 送信を始めると、DACを中心値にしてからPTTをオンにする
  2. PTT_ON_DELAY_MS (300ms) 待つ(無線機が送信状態になるまで)。この間は音声を出さない
  3. プリアンブルから最後のフラグまで送出する
  4. PTT_OFF_DELAY_MS (50ms) 待ってからPTTをオフにする。PTTをオフにしてからDACを止める
  5. 受信に戻る
  - PTTのオン時間が PTT_MAX_ON_MS (10秒) を超えたら、送信を中止してPTTを強制オフにし、受信に戻る。画面に「PTT時間超過: 送信を中止」と出し、動作ログに `ptt_timeout` を記録する。中止した回数は送信・設定画面に出す。中止のあとも次の送信はできる
  - 起動時、他の初期化より先にPTTをオフにする
  - 通常の送信は、PTT待ち+プリアンブル(60フラグ=約0.4秒)+フレーム+余韻で、1〜2秒程度
  - PTT_PIN を -1 にするとPTT出力なし(従来どおり、待ち時間も入れない)
  - 送信中は画面に「PTT ON」を表示する(自局画面と送信・設定画面。画面右上は「[PTT送信中]」)
- DAC出力のタイミングは、タイマ割り込みで制御する。割り込みの中ではサンプルの出力だけを行い、処理時間の長いこと(パケット生成、画面更新、SD書き込み)は割り込みの外で行う。波形のサンプル列は、送信前に用意しておく [案]

### 4.3.1 調整トーン(減衰回路・送信レベルの調整用)
- 設定メニューの「調整トーン (PTT送信)」でB短押しすると、調整トーン画面が開く。無線機は**ダミーロード・最小電力**につなぐ前提
- 画面の操作(停止中): A=前のモード、C=次のモード、B短押し=開始、B長押し=メニューへ戻る。A長押し(送信)・C長押しは何もしない
- モード: 1200Hz連続(MARK)、2200Hz連続(SPACE)、1200Hz⇔2200Hz交互(0.5秒ごと、位相は連続)。振幅は通常の送信と同じ(TX_AMP_MARK / TX_AMP_SPACE)
- 開始すると、通常の送信と同じ手順でPTTを入れ(PTT_ON_DELAY_MS待つ)、止めるまで連続トーンを出す。モニター音も出る
- 出力中は、**どのボタンでも押した瞬間に停止**する。CALIB_MAX_ON_MS (30秒) で自動停止する。停止後は PTT_OFF_DELAY_MS 待ってPTTを切り、受信に戻る
- 調整トーンは送信回数に数えない。PTT_MAX_ON_MS の時間超過にも数えない(それとは別に、CALIB_MAX_ON_MS+2秒を超えたら強制オフ)
- 画面右上は「[調整中]」。開始と停止は動作ログ(`calib`)に残る

### 4.3.2 シリアルモニタへの診断出力(115200bps)
- DIAG_SERIAL が1のとき、PCのシリアルモニタに診断を出す。ASCIIのみで、行頭は起動からの時間 `[ 秒.ミリ秒]`
- 出る内容:
  - 起動時: `BOOT`(局、AFSK初期化の成否、バージョン、ビルド日時、基板の版)、`CFG`(ピン、PTTの待ち時間、サンプルレート、振幅、プリアンブル数)
  - PTTと送信の経過: `PTT ON` / `TX audio start (+300ms after PTT)` / `TX audio end (…ms)` / `PTT OFF (on …ms)` / `PTT TIMEOUT` / `CALIB start|stop`
  - パケット: `TX pkt:`(送信したTNC2形式)、`RX pkt:`(受信したTNC2形式)
  - 受信の状態の変化: `RX signal|data|idle`(入力のピーク、MARK/SPACEの強さ、直流のずれ、連続フラグ数、振り切れ)、`RX ok`、`RX fcs-error`。ノイズで開閉が速いときは間引く(100ms未満の変化は出さず、数えて次の行で知らせる)
  - 定期の状態(DIAG_STATUS_INTERVAL_MS、既定5秒。0で出さない): `STAT` の3行(GPS・位置・SD、受信/送信の統計とPTT時間超過回数と空きメモリ、入力のピークとMARK/SPACEの強さと直流のずれ)。送信中・信号受信中は1回見送る
- 診断は受信の動作を変えない。ただしシリアルへの書き込みでloopが少し遅れるため、出す行は短く間引いてある
  - 自動送信: `AUTO TX mode=…`(設定の変化)、`AUTO TX beacon`、`AUTO TX waiting for clear channel`、`AUTO TX skipped: channel busy|no position`

### 4.3.3 ビーコンの自動送信
- 設定メニューの最初の項目「ビーコン自動送信」で選ぶ: オフ / Ackのみ / 1・2・3・5・10・15・30・60分ごと(AUTO_TX_INTERVALS_MIN) / フレックス(0.12.0)。選択肢が11個で入りきらないので、選択中の前後を出す。本体(不揮発領域)に保存し、電源を入れ直しても引き継ぐ。保存値がないときは DEFAULT_AUTO_TX(オフ)
  - オフ: 自動では何も送らない(メッセージのAckも返さない)
  - Ackのみ: ビーコンは出さず、自分宛てメッセージのAckだけ自動で返す(Ackの処理はメッセージ機能で実装)
  - 間隔: その間隔でビーコンを送る。Ackも自動で返す
  - フレックス: 速度と曲がり方で間隔を変えて送る(下記)。Ackも自動で返す。英語表示は Flexible
- 最初の送信: 間隔を選んだ時点(起動時は起動した時点)から数え、間隔が過ぎたら送る。すぐには送らない
- 送ったら(自動・手動とも)、そこから数え直す。同じ間隔を選び直しても数え直さない
- 送る時刻に他局が送信中(信号あり)なら、止むまで待つ。BEACON_BUSY_WAIT_MS(30秒)待っても止まなければ、その回は見送り、次の間隔へ(画面に一時表示、動作ログに `tx_skip auto_channel_busy`)
- 自局の送信中・調整トーン中は、終わるまで待つ(見送りにはしない)
- 位置がないときは送らず、次の間隔へ(画面に「自動送信: 位置がないため見送り」、動作ログに `tx_skip auto_no_position`)
- 表示: ヘッダーの自動送信アイコン(4.5)。自局画面の「送信内容:」の行に「次の自動送信まで m:ss」(待ち中は「自動送信は他局の送信待ち」)。送信・設定画面に「自動送信: 5分 (次 m:ss)」
- 動作ログ: 設定の変化 `auto_tx`(値は `5min` `ack_only` `off` `flex` `flex_no_config`)、自動で送ったとき `tx_auto beacon`
- フレックス(0.12.0): 八重洲・ケンウッドの無線機のスマートビーコニングと同じ方式・同じ項目。値は config.txt(3.1)
  - 速度 < flex_low_speed: flex_slow_rate ごと。速度 > flex_high_speed: flex_fast_rate ごと。その間: flex_fast_rate × flex_high_speed ÷ 速度 ごと(走った距離がだいたい一定になるごと)
  - 曲がったとき: 前回送ったときの進行方向から「flex_turn_angle + flex_turn_slope × 10 ÷ 速度」度より大きく変わり、前回から flex_turn_time 以上たっていれば、間隔を待たずに送る。速度が flex_low_speed 以上のときだけ(遅いときの向きは当てにならない)。前回送ったのが止まっていたときなら、動き出したときの向きを基準にする
  - 遅いときの距離(独自の追加。flex_slow_dist が 0 でないとき): 速度 < flex_low_speed でも、前回送った位置から flex_slow_dist 以上離れ、前回から flex_turn_time 以上たっていれば送る(のろのろ走って止まったとき・歩いたときに位置が古くならないように)
  - 速度・進行方向・位置は、位置の取得元が GPS で、FLEX_FIX_MAX_AGE_SEC(5秒)以内の測位に速度があるときだけ使う。そうでなければ(最後の位置・固定位置、測位なし)flex_slow_rate ごと
  - config.txt に値がそろっていなければ、メニューでは「フレックス (config.txt に設定なし)」と出して飛ばす。保存されていた選択がフレックスなら、ビーコンは送らず(Ackは返す)、自局画面に「フレックスの設定なし」
  - 表示: 「次の自動送信まで」は今の速度での間隔から出す(曲がったときはそれより早く送ることがある)。送信・設定画面は「自動送信: フレックス (次 m:ss)」

### 4.4 AFSK受信・デコード
- ADC(GPIO36)を RX_SAMPLE_RATE_HZ で連続サンプリング。常時動作する(送信中は停止)
- サンプリングはタイマ割り込みで行う。割り込みの中では、ADC値をリングバッファに入れるだけにする。復調とパケット処理は、割り込みの外のタスクで行う。SD書き込みなどで処理が遅れても取りこぼさないよう、リングバッファに数十msぶん以上の余裕を持たせる [案]
- 復調方式: 1200bps AFSK (Bell 202) を、直交相関検波で復調する
  1. 入力の整え: 直流バイアスを除き、帯域フィルタ(おおよそ1000〜2500Hz)を通す。振幅はAGCでそろえる
  2. 相関の計算: 1200Hz(MARK)と2200Hz(SPACE)それぞれについて、sinとcosの参照波との積を、1ビットぶん(RX_SAMPLE_RATE_HZ=13200Hzなら11サンプル)の窓で足し合わせる。窓は1サンプルずつずらす(スライディング)
  3. 判定: 各トーンの強さ(sinとcosの2乗和)を比べ、強いほうをMARK/SPACEとする
  4. 補正: 1200Hzと2200Hzの強さの比が崩れていても判定できるよう、トーンごとの強さの平均を追い続け、比較の前にその平均で割ってそろえる。補正の初期値は `config.h` の定数にする(新しい定数が必要な場合は、コード側で仮定せず提案する)
  5. ビット同期: トーンが切り替わる位置から、サンプリング位置を少しずつ前後に動かす(デジタルPLL)
  6. 以降は、次のHDLC処理に渡す
  - 計算は、整数(固定小数点)で行う
  - 計算は割り込みの外のタスクで行い、割り込みの中ではADC値をバッファに入れるだけにする
- HDLC処理: NRZI復号、フラグ検出、ビットデスタッフィング、FCS検証。FCSが合わないフレームは捨てる
  - 信号あり(下記)のときだけビットを HDLC 処理に渡す。信号がなくなったら、組み立て中のフレームを数えずに捨てる(0.13.3)。M5Stack 内部の雑音(画面の描き直しの SPI など)や ADC の雑音を解読して、偽のフラグ・エラーを数えないため。しきい値より弱い信号は解読しない
  - 数え方: 長さが正しく(バイト単位で17バイト以上)CRC が合わないものは「CRC不良」(本物の受信失敗)。フラグの間の半端なかけら(バイト単位でない・短すぎる。主に信号の端の雑音)は「雑音」として別に数える(0.13.3。以前は両方を FCS不良 に数えていた)
- 受信状態の判定(画面表示用。受信の動作は変えない):
  - 信号あり: MARK/SPACEどちらかのトーンの強さが一定以上(振幅が約40以上)になった。50msは保持する(ハング)。ノイズも含む
  - データ受信中: 信号ありで、フラグ(0x7E)が RX_DATA_SYNC_FLAGS 個(3)連続した。AFSKのパケットが来ていると判断する
  - 受信OK / FCS不良: フレームが完成したときの結果。RX_RESULT_SHOW_MS (2秒) 表示する
  - MARK/SPACE の強さの比: そのトーンが明らかに優勢(相手の8倍以上)なときの強さの平均から出す(0.13.3)。2200Hz は1ビットの窓(11サンプル)に整数周期で入らないため、MARK の間も SPACE の相関に MARK の約4割が漏れて見える。0.13.2 までは強さのピークから比を出していたので、真の比が大きいほど小さく出ていた(真の 2 が 1.6、6 が 2.4)
  - 最後に正しく受けたパケットの比も覚えておき、受信状態画面の「直近」の行に出す(調整トーンでなく、実際の局の比を見るため)
  - 入力レベル: ADC値の振幅(ピーク。ゆっくり減衰)と、振り切れの検出。MARK/SPACEそれぞれのトーンの強さと、その比
  - 送信中は受信していないので「信号なし」とする
  - 入力の振り切れ: ADC値が端(約±2000以上)に当たり、かつ信号が振れている(直流分を除いた値が300以上)ときだけ「振り切れ」とする。入力が開放やバイアス不良で端に張り付いているだけ(振れていない)では「振り切れ」としない
  - 直流分のずれ: ADC値の中心(2048)からのずれを推定して表示する。±1000以上なら受信状態画面に「ADC入力の直流が範囲外 (配線・バイアス確認)」と出す
- 受信対象の位置レポート形式: 非圧縮形式(`!` `=`、時刻つきの `/` `@`)、圧縮形式(同じデータ種別。0.11.0)、Mic-E。オブジェクト・アイテムなど、それ以外は位置として読まない
- 圧縮形式(APRS101 第9章): データ種別(と時刻)の次の文字が数字でなければ圧縮形式として読む。`/YYYYXXXX$csT` (記号の表、緯度4文字・経度4文字の91進数、記号、cs、種別)
  - 緯度 = 90 − (4文字の値) ÷ 380926、経度 = −180 + (4文字の値) ÷ 190463 (各文字は文字コード − 33 の91進数)
  - 記号の表の `a`〜`j` はオーバーレイの数字 `0`〜`9` として扱う
  - cs: 空白なら無し。1文字目が `{` なら電波の範囲 (使わない)。種別の NMEA の欄が GGA なら高度 1.002^(c×91+s) フィート。それ以外は進行方向 c×4 度・速度 1.08^s − 1 ノット (c, s は文字コード − 33)
  - 記号が `_` (気象局) なら、cs は風向・風速 (ノット)。コメントの g t r p P h b … を気象データとして読む
  - 受信ログの種類は `compressed`
- ステータス `>`(先頭の時刻 DDHHMMz を除く)、機能の通知 `<`、第三者パケット `}`、テレメトリ `T#` を種類として見分ける(中身は読まない)
- Mic-E の復号(APRS101 第10章)。コメントの先頭・末尾の機種の印(APRS 1.2: Kenwood `>` `]` と末尾 `=` `^` `&`、Yaesuなど `` ` `` `'` と末尾2文字 `_(` `_1` `|3` など)は取り除く。機種名は詳細画面だけに出す
- 宛先(TOCALL)から機種を見分ける(Mic-E 以外。0.14.0): aprs-deviceid の tocalls.yaml から tools/gen_tocalls.py で作った表(tocalls_table.h、約480件)。SSID は無視。形の記号 `?`=任意の1文字、`n`=数字、`*`=以降なんでも。決まった文字の多い形から順に調べ、最初に合ったものを使う。汎用の `APRS` と表にないものは機種なし。機種名は19バイトまで(長いものは切る)。表の更新: `python3 tools/gen_tocalls.py <tocalls.yaml> > tocalls_table.h`
- 情報欄の末尾の改行(CR/LF)は取り除いてから読む
- 重複: 送信元・宛先・情報欄が同じパケットを30秒(RX_DUPE_MS)以内に受けたら(複数のデジピーター経由など)、2回目以降は受信一覧・WX・メッセージの処理をしない。受信ログには両方残す
- メッセージ(APRS101 第14章): 4.8
- 気象データ(APRS101 第12章): シンボル `_` の非圧縮位置レポート(位置のあとの `ddd/sss` は風向/風速)と、データ種別 `_` の位置なしレポート(`_MMDDHHMM` のあと)。項目 c(風向) s(風速) g(突風) t(気温℉、負号可) r/p/P(雨量 1時間/24時間/0時から、1/100インチ) h(湿度、00=100%) b(気圧 1/10hPa) L/l(日射)。`.` や空白の項目は不明。読めない文字から先はコメント。メートル法(℃、m/s、mm、hPa)に直す。圧縮形式やPeet Brosなど機器独自の形式は対象外
  - 識別子は `` ` `` と `'`。情報フィールドが9バイト未満なら、そのパケットは無視
  - 宛先アドレス: 緯度6桁、メッセージコード(A/B/C)、N/S、経度オフセット(+0/+100度)、W/E、SSIDにデジパス。緯度の桁がスペースなら曖昧化
  - 情報フィールド: 経度(d+28、m+28、h+28)、速度・進行方向(SP+28、DC+28、SE+28。符号化方式が2通りあり、両方に対応)、シンボルコード、シンボルテーブルID、ステータス文またはテレメトリ
  - 情報フィールドは、印字できない文字を含むバイト列として扱う
  - ステータス文の先頭に、ケンウッド機の種別コード(`>` または `]`)が付く場合は読み飛ばす
  - 高度は、ステータス文の中の `xxx}` を探して復号する。3文字それぞれから33を引いて91進数の3桁の値にし、そこから10000を引くとメートルになる(例: `"4T}` は61m。基準は海面下10km)
- 非圧縮形式のコメントに高度 `/A=aaaaaa` (フィート)が含まれる場合も、高度として読み取る(1フィート=0.3048m)。高度は、メートルに統一して表示・記録する
- 位置を含まないパケット(メッセージなど)も、受信一覧とログに記録する。画面には「位置情報不明」と表示し、ログでは位置・距離・方位を空欄にする

### 4.4.1 受信音 (0.13.0)
- 受信したパケットの種類で音を分けて、内蔵スピーカー(モニターと同じ DAC GPIO25)で鳴らす。受信の割り込みの中で矩形波を出す
  | きっかけ | 音 | 中身 |
  |---|---|---|
  | パケットを受信 | 「ポッ」 | 825Hz 40ms |
  | 折り返し(送信元が自局と同じコールサイン・SSID。デジピーターで戻ってきた) | 「ポピッ」 | 943Hz 60ms → 1650Hz 80ms |
  | 送ったメッセージに Ack が来た | 「ピコーン」 | 1320Hz 80ms → 1650Hz 200ms |
  | 自分宛てメッセージ・一斉通知を受信 | 「ピピピッ」 | 1100Hz 100ms ×3(間 60ms) |
- 1つのパケットで鳴らすのは1つだけ(メッセージ・Ack > 折り返し > パケット)。Rej は「ポッ」。重複(30秒以内の同じパケット。2回目以降の折り返しも)は鳴らさない
- 音量は設定メニューの「受信音の音量」(オフ・1〜4。振れ幅は CHIME_AMP_TABLE で DAC の中心から ±1 / ±4 / ±9 / ±20 (0.13.1。0.13.0 は ±4 / ±11 / ±26 / ±60 で大きすぎた)。モニター音量とは別に保存)。オフなら鳴らさない。ヘッダーの鈴のアイコンで示す
- パケットを受け終わってから鳴らす。鳴っている途中に次の音が来たら入れ替える。送信を始めると止まり、送信中は鳴らさない

### 4.5 画面とボタン
ボタンの共通ルール: 短押しは「その画面の中の操作」、長押しは「どこでも同じ働き」。

| ボタン | 短押し(画面の中) | 長押し(どこでも同じ) |
|---|---|---|
| A | 前(前の画面・項目・モード) | ビーコン送信(通常画面のみ。設定メニュー・調整トーンでは何もしない) |
| B | 決定(詳細を開く・値の切り替え・開始) | 戻る(1つ上へ。通常画面では何もしない) |
| C | 次(次の画面・項目・モード) | 設定メニューを開く/閉じる |

- 長押しは、長押しの時間(LONG_PRESS_MS)に達した時点で1回だけ働く(離すのを待たない)。同時押しは無効
- ヘッダー(0行目): 左に画面名(半角21桁まで。「n/6」の番号は出さない)。右に状態アイコンを8つ、定位置・等幅(16×16ドット、間隔18ドット)で並べる。表示するものがない枠は空ける

  |---|---|---|
  | 1 | 電池 | 4段階(残り1段=赤、2段=黄、3〜4段=緑)。充電中は黄の稲妻を重ねる。不明は灰 |
  | 2 | SDカード | 正常=緑、エラー・未挿入=赤に斜線 |
  | 3 | 音量 | 上向きのスピーカーと「)」の弧(最大4本)。ミュートは赤い× |
  | 4 | 受信音 | 上半分に白い鈴、下半分に音量: 1=中央の短い線、2〜4=両側の弧を1組ずつ足す(外側ほど高い蝶ネクタイ型。まだ鳴っていない弧は暗い灰)。鳴らさない設定は赤い×(0.13.0) |
  | 5 | GPS/位置 | 取得元がGPS: 衛星(測位中=緑、測位待ち=灰、途切れ=黄、受信なし=灰に赤い斜線)。最後の位置=橙の「L」、固定位置=橙のピン |

- 本文には操作の説明を出さない(ボタン表示で分かるため)。本文はヘッダーを除いて12行まで

画面は7つ(ボタンA=前、C=次で循環)。このほかに設定メニューから開く「調整トーン」画面(4.3.1)と、メッセージ画面から開く「メッセージ作成」がある(4.8):
1. 自局画面: GPS測位状態と衛星数(取得元がGPS以外のときは取得元)、位置(1行。「位置 35.68123N 139.76712E」)、時刻、GPS未受信/未測位の警告、送信内容のプレビュー(選択中のシンボル・SSID、デジパス、曖昧化レベルを含む。「送信内容:」の行の先頭に自局のシンボルのアイコン)。受信中・送信中はヘッダーの稲妻で分かる(誰かの通信に重ねて送信しないため)
2. 受信一覧: 1件を2行で表示する。1行目は受信時刻、送信元(コールサイン-SSID)、自局からの距離と方位、速度(km/h。送られていないときは「-km/h」)。1行目の先頭(半角2桁)にシンボルのアイコン(4.5.4)。2行目は高度(m。ある場合)とコメント(アイコンの無いシンボルは、2行目の先頭に文字で `\n` のように出す)。1行目が38桁を超えるときは、時刻の秒を省く。位置がないパケットは、1行目に種類(ステータス / 機能 / iGate経由 / メッセージ / 気象 / その他)、2行目に本文を出す。ステータスは先頭の時刻を除いた本文、メッセージは「→宛先 本文」、位置なしの気象は主な値、本文が空なら「(空)」。テレメトリ(`T#`)は一覧に出さない(受信ログには残す)。
   - B短押しで、いちばん新しい1件の詳細を開く。詳細ではA/Cで前後(一覧に出ていない分も含めRX_LIST_COUNT件を一周)、B長押しで一覧へ、B短押しでその局を宛先にしたメッセージ作成(本文の選択から。自局の折り返しでは使えない)
   - 詳細: 送信元、受信時刻と経過時間、種類(Mic-Eは状態「En Route」など)、機種名(Mic-E は印から、それ以外は宛先 TOCALL から。どちらも aprs-deviceid の表。0.14.0 から Mic-E 以外も)、位置、距離と方位、速度と進路、高度、シンボル、経路、コメント全体(3行まで)。シンボルのアイコンを 32x32(16x16を2倍)で、1・2行目の右端に出す(この2行は33桁まで)。1行目は「送信元 時刻Z 経過時間」(例: `N0CALL-3 14:22:41Z 46分25秒前`。Z は UTC)。位置なしは種類・宛先(メッセージ)・経路と本文
   - 距離・方位は、選択中の位置の取得元の位置から計算する。画面に出す件数はRAM上の直近分(RX_LIST_COUNT件)で、全件はmicroSDに保存する(4.7)。30秒以内の同じパケットは1件にまとめる(4.4)
3. レーダー画面: 4.5.5
4. メッセージ画面: 4.8
5. WX(気象)画面: 4.5.1
6. 受信状態画面: 受信の状態(無信号 / 信号あり(AFSKは未確認) / データ受信中 nバイト / 受信OK / FCS不良)、入力レベルのバー(振り切れは赤、小さすぎると黄)、MARK(1200Hz)とSPACE(2200Hz)のトーン強度のバー、MARK/SPACEの強さの比(適正範囲で色分け)、受信OK件数・CRC不良件数・雑音の件数(4.4)、フラグ検出数・途中破棄数、取りこぼし数・待ち行列破棄数、直近に受信した局と、そのパケットの MARK/SPACE の比。受信中は文字行の更新を見送り、バーだけ約100msごとに更新する(受信のサンプルの取りこぼしを避けるため)。この画面を表示し続けているときは、信号が続く間ずっと文字行を見送る(0.13.3。ほかの画面は最長1秒。長い調整トーンで取りこぼさないように)
7. 送信・設定画面: 局(コールサイン-SSID)、シンボル(文字と名前)、デジパス、曖昧化、進行方向・速度、高度、自動送信、送信回数と最後の送信、送信中は「PTT ON」(PTT時間超過で中止した回数があれば表示)、設定保存の状態、稼働時間(位置の取得元・モニター音量・SDの状態はヘッダーのアイコンで示す。SDの書き込み待ちバイト数はバージョン情報に出す)

設定メニュー(C長押しで開く):
- 項目: ビーコン自動送信(オフ / Ackのみ / 間隔 / フレックス。4.3.3)、位置情報の曖昧化(レベル0〜4)、デジパス(3候補)、シンボル(21種類。4.5.4。行の3桁目にアイコン。入りきらないので選択中の前後10個を出す)、SSID(0〜15。用途の説明付き: 0=SSIDなし(固定局)、7=ハンディ機、9=モービル など)、進行方向・速度の送信(オン/オフ)、高度の送信(オン/オフ)、モニター音量(ミュート〜最大の5段階)、受信音の音量(オフ〜最大の5段階。モニター音量とは別。変えると試しにメッセージの音を鳴らす。4.4.1)、画面の明るさ(5段階。1=夜間(バックライト 1)、4=日中 0.5.0までの明るさ、5=直射日光の下。BRIGHTNESS_TABLE。変えるとすぐ反映し、本体に保存)、位置の取得元(GPS / 最後の位置 / 固定位置)、固定位置の選択(取得元が固定のときだけ表示。設定済みの欄の中から選ぶ)、調整トーン(PTT送信)(B短押し「開く」で調整トーン画面を開く。この項目では送信しない)、記録の消去(B短押し「開く」で記録の消去の画面を開く。4.5.6)、言語 / Language(日本語 / English。4.5.3)、バージョン情報(表示のみ。4.5.2)。項目ごとに専用のメニューで設定する。画面には「設定 n/m」(mは表示中の項目数)を出す
- 操作: A=前の項目、C=次の項目、B短押し=値の変更(ボタン表示は「変更」)または決定、B長押しまたはC長押し=メニューを閉じる(開いたときの画面に戻る)

### 4.5.1 WX(気象)画面
- 気象データを含むパケットを受信した局を、SSIDに関係なく全部表示する。局ごとに最新の値を持つ(WX_STATION_COUNT=8局。超えたら受信がいちばん古い局と入れ替える。ただし詳細を表示中の局は残す)。microSDに保存し、再起動後も残る(4.7.1)
- 位置なしの気象レポートを受けたときは、その局の前の位置(と距離・方位)を残す。距離・方位は受信したときの自局の位置から計算する
- 一覧: 新しい順に1局3行で最大4局。1行目 コールサイン、受信時刻(UTC)、距離と方位、経過時間。2行目 気温・湿度・気圧。3行目 風向・風速・突風・1時間雨量。値がない項目は `--`。WX_STALE_MS(60分)を超えて受信がない局は灰色で残す(消さない)。5局以上は「ほかn局」
- 詳細: 一覧でB短押しすると、いちばん新しい局の詳細を開く。A/C=前後の局(一周)、B長押し=一覧へ。項目は、受信時刻と経過、位置と距離・方位、気温、湿度、気圧、風向(度と16方位)、風速、突風、雨量(1時間・24時間・0時から)、日射(あるとき)、受信回数、コメント
- 詳細の中でも A長押し=送信、C長押し=設定メニュー は使える(メニューを閉じると詳細に戻る)

### 4.5.2 バージョン情報
- ファームウェアのバージョンは `version.h` の FW_VERSION で持つ。形式は メジャー.マイナー.パッチ(初版 0.1.0)。リリースのたびに手で書き換える。gitのコミットIDは埋め込まない
- 設定メニューの最後の項目「バージョン情報」に表示する(切り替える値はない。B長押しで閉じる):
  - 名前とバージョン(例: `M5APRS  ver 0.1.0`)
  - 著作権の表示(`Copyright (c) 2026 Minato Suzuki`。version.h の FW_COPYRIGHT。LICENSE と同じ)
  - ビルド日時(コンパイラの __DATE__/__TIME__。日付は `2026-10-18` の形に直す)
  - 対応するインターフェース基板の版(HW_INTERFACE_REV。例: `IF v1`)
  - コールサイン(MY_CALLSIGN)
  - ESP32 SDKのバージョン、チップのリビジョン、空きメモリ
  - SDの状態と書き込み待ちのバイト数
- シリアルの起動時の `BOOT` 行にも、バージョン・ビルド日時・基板の版を出す(4.3.2)

### 4.5.3 表示の言語
- 設定メニューの「言語 / Language」(バージョン情報の前)で、日本語 / English を選ぶ。B短押しですぐ切り替わり、本体に保存する。初期値は `config.h` の DEFAULT_LANGUAGE(0=日本語、1=English)
- 項目名は、どちらの言語でも「言語 / Language」と両方を出す(読めない言語にしてしまっても戻せるように)
- 切り替えるのは画面の表示(本文、見出し、ボタン)だけ。送信するパケット、定型文、microSDのログ、シリアルの診断出力は変えない
- 英語の文は `ui_text.cpp` の対訳表に持つ。日本語の文がそのまま表の見出しになる(画面は `L("…")`、ボタンは `K("…")`。ボタンは「送信」=TX / Send のように画面の文と訳が違うので別の表)
- 英語でも1行38桁、見出し23桁、ボタン13桁(長押しの「Hold:」を含む)に収まること。`tests/check_i18n.py` が、表に無い日本語の文、書式指定(%sなど)の食い違い、長すぎる訳を調べる
- 送信中はボタンを受け付けない。送信中に押し始めたボタンは、送信が終わってから離しても無効

### 4.5.4 シンボルとアイコン
- 設定で選べるシンボル(21種類、すべてプライマリ表): 車 `/>`、トラック `/k`、大型トラック `/u`、バン `/v`、ジープ `/j`、キャンピングカー `/R`、バス `/U`、オートバイ `/<`、自転車 `/b`、徒歩・ハンディ `/[`、船(動力船) `/s`、ヨット `/Y`、小型機 `/'`、ヘリコプター `/X`、気球 `/O`、自宅 `/-`、自宅(八木) `/y`、テント(移動運用) `/;`、ノートPC `/l`、気象局 `/_`、デジピーター `/#`
- アイコンは16x16の単色のドット絵(M5APRS用に描いたもの。`symbols.cpp`)。上の21種類と iGate の22個
- 色: 移動する局(乗り物・人・テント・ノートPC・気球・飛行機)=白、常置場所(自宅)=水色、気象=黄、機能のあるもの(デジピーター・iGate)=緑
- 受信したシンボルのアイコン: プライマリ表は上の21種類。代替表(オーバーレイ付きを含む)の `&` は iGate(`I&` `R&` `T&` など)、`#` はデジピーター(`1#` `I#` など)。代替表のうち意味の近いものはプライマリ表のアイコンを当てる(0.11.0): `>` 車(`S>` `H>` など)、`v` バン、`k` SUV→ジープ、`u` トラック→大型トラック、`s` 船(`Ys` はヨット)、`^` 航空機→小型機、`-` 家→自宅。代替表には意味の違う記号も多い(`\[` は壁雲、`\O` はロケットなど)ので、それ以外はアイコンなし(文字で出す)
- 出す場所: 設定のシンボル一覧、自局画面、受信一覧、受信詳細(32x32)

### 4.5.5 レーダー画面
- 自局の位置(選択中の取得元の位置)を中心、北を上にして、時間内に受信した局をシンボルのアイコン(16x16。アイコンの無いシンボルは白い点)とコールサイン(小さい英数字 6x8)で描く。外側の円が表示中の距離、内側の円がその半分(円の横に km の目盛り)。自局は中心の赤い十字
- 局の表: 位置を含むパケットを受信するたびに、局ごとに最後の位置・シンボル・受信時刻を覚える(RADAR_STATION_COUNT=40局。超えたら受信がいちばん古い局と入れ替える)。今の自局(コールサインとSSIDが一致)は入れない(デジピーターの折り返しで中心に重なるため)。SSIDが違う同じコールサインの局は別の局として入れる。state.bin に保存し、再起動後も残る(4.7.1)
- 時間: 10分 / 30分 / 1時間 / 3時間 / 6時間 / 12時間 / 24時間(0.10.1 で6〜24時間を追加)。覚えておく局は40局までなので、長い時間では古い局が入れ替わって出ないことがある。受信からの経過時間がこれより長い局は出さない。再起動前の局は、保存したUTCと今のGPSのUTCから経過時間を出す(どちらかが分からなければ出さない)
- 距離: 1 / 2 / 5 / 10 / 20 / 50 / 100 km と自動。自動は、時間内でいちばん遠い局が入るいちばん小さい距離(100kmを超える局があれば100km。局が無ければ10km)。円の外の局は描かず、数だけ出す
- 右側: 距離(自動のときは「自動」と決まった距離)、時間、円の中の局の数、範囲外の局の数、いちばん近い局のコールサインと距離・方位。自局の位置が無いときは「自局位置なし」、時間内の局が無いときは「受信局なし」。1行は13桁まで(英字は字によって幅が広いので余裕を持たせ、欄の外には描かない)
- 見出し: 「レーダー 10km/1時間」
- 操作: B短押しで切り替えモードに入る/抜ける。モード中は A短押し=距離、C短押し=時間を次の値へ(ボタン表示は「距離 / 終了 / 時間」、右側の距離と時間を水色にする)。モードの外では A/C は前後の画面。長押し(A=送信、C=設定)はモード中も同じ。自動では抜けない。画面を移ると抜ける
- 選んだ距離と時間は本体に保存する(4.6。初期値は fw_config.h の DEFAULT_RADAR_RANGE=自動、DEFAULT_RADAR_TIME=1時間)
- 描き直し: 中身(局の位置・文字)が変わったときだけ、円の範囲と右側を描き直す

### 4.5.6 記録の消去 (0.13.3)
- 設定メニューの「記録の消去」で B短押し「開く」→ 消す対象を選ぶ: 受信一覧 / WX局 / メッセージ / レーダーの局 / すべて(それぞれ件数を出す)
- A/C で対象を選び、B「選択」で確認(「「受信一覧」を消去します」)、もう一度 B「消去」で消す。確認中の A/C「やめる」で取り消し。B長押しでメニューに戻る
- メッセージを消すと、送り直し中のものも止まる。メッセージ番号は続きから使う。返す予定の Ack は残す
- 消したら画面に「消去しました: 対象」を出し、動作ログに `clear rx|wx|msg|radar|all`。保存ファイル(state.bin)には次の定期保存で反映される

### 4.6 設定値の保存
- `fw_config.h` の値を初期値とし、メニューで変えた値はESP32の不揮発領域(Preferences、NVS_NAMESPACE)に保存する
- 保存する設定: 曖昧化レベル、デジパス、シンボル、SSID、進行方向・速度の送信、高度の送信、自動送信、モニター音量、受信音の音量、画面の明るさ、位置の取得元、固定位置の選択、表示の言語、レーダーの距離と時間(15個の値)
- 0.7.0 までの「シンボル・SSID」のプリセット(キー preset)だけが保存されているときは、起動時にシンボルとSSIDに直して使い、新しいキー(sym、ssid)に保存する(例: Car → `/>` と 9、Home → `/-` と SSIDなし)
- 別に、「最後の位置」を保存する(4.1.1。設定とは別のデータ)
- 保存のタイミング: 値を変えるたび。ただし、値が実際に変わったときだけ書き込む
- 送信中と、信号を受信している最中には書き込まない(終わってから書き込む)
- 起動時は、保存値があればそれを使い、なければ `fw_config.h` の初期値を使う

### 4.7 microSDへの記録
- M5Stack Basic内蔵のmicroSDスロット(CS=GPIO4)を使う。LCDとSPIバスを共有するため、画面更新とSD書き込みが同時にならないよう、排他制御する [案]
- 受信したパケットは、すべてmicroSDに保存する(位置がないものも含む)
- 受信ログ: CSV形式 [案]。1パケット1行。項目は、受信日時、送信元、デジパス、形式(uncompressed / mic-e / weather / message / status / telemetry / capabilities / third-party / other)、緯度、経度、高度(m)、距離(km)、方位(度)、シンボル、コメント、生パケット(TNC2形式) [案]
  - 位置情報がないパケットは、緯度・経度・高度・距離・方位を空欄にする。高度だけがないパケットは、高度を空欄にする
  - 自局位置が不明で、距離・方位を計算できない場合も、空欄にする
- 動作ログ: 送信したパケット、GPSの受信・測位の状態変化、位置の取得元の変更、PTT時間超過、受信の取りこぼし・途中破棄・待ち行列破棄、SDカードのエラーと復旧、起動(boot)を、別のログファイルに記録する
- ログ(受信ログと動作ログの2本)は、日付ごとにファイルを分ける。保存先は LOG_DIR
  - 受信ログ `rx_YYYYMMDD.csv`。ヘッダ: time_utc,src,via,type,lat,lon,alt_m,dist_km,bearing_deg,symbol,comment,raw
  - 動作ログ `ops_YYYYMMDD.log`。ヘッダ: time_utc,uptime_ms,event,detail
  - 日付と時刻はGPSのUTC。日付が得られないときは `nodate` のファイルに記録する
  - 生パケット(raw)はTNC2形式。表示できないバイトは `\xHH`、バックスラッシュは `\\` で書く
- 記録はまずRAMの待ち行列(8KB)に入れ、信号を受信していないときにSDへ書く。書き込みに失敗したら10秒後に再試行し、溜まった分を書く。あふれたら古いものから捨てて、捨てた件数を記録する
- microSDが挿入されていない、または書き込めない場合でも、送受信と画面表示は続ける。画面にSDのエラーを表示する
- SD書き込みは、受信のサンプリングを妨げないよう、割り込みの外で行う
- 距離と方位: 自局の位置(選択中の位置の取得元。GPSのときは、最新の測位位置。測位が失われている間は、5分以内の最終測位位置)から、受信した位置までの大円距離(km)と初期方位(真北基準、度)を計算する

### 4.7.1 再起動後の復元
- 受信一覧(RX_LIST_COUNT件と受信の合計数)、WX局、メッセージ(受信・送信・一斉通知、未読・既読を含む)、レーダーの局の表を、LOG_DIR の `state.bin` に保存し、起動時に読み込む
- 書き込み: 30秒(STATE_SAVE_INTERVAL_MS)ごとに内容を作り、前回保存した内容とCRC32が違うときだけ書く。受信のサンプルを取りこぼさないよう、1回に2KBまでとし、送信中・受信中は止める。いったん `state.bin.tmp` に書いてから置き換える(途中で電源が切れても、前のファイルか新しいファイルが残る)。最後の書き込みから電源を切るまでの分(最大30秒ほど)は失われることがある
- 読み込み: 受信の割り込みを始める前に行う。ファイルがない、壊れている(CRC不一致)、ファームウェアの変更で形式や件数が違うときは、読み込まずに空で始める。結果は動作ログに `state_restore` で記録する
- 送り直しの途中だったメッセージは「応答なし」にする(再起動で勝手に送信を再開しない)。Ackの返送待ちも引き継がない
- 経過時間: 受信・登録の時刻をGPSのUTC(1970年からの秒)でも持つ。再起動前のものは、起動後にGPSの時刻が取れたらUTCの差で経過時間を出し、取れるまでは「--」と表示する。WX局は、経過時間が分からない間は灰色(「再起動前のデータ」)にする
- 起動後に受信したものは、再起動前のものより新しいものとして並べる

### 4.8 メッセージ
- 受信(APRS101 第14章 `:ADDRESSEE:本文{番号`):
  - 自分のコールサイン宛て: SSIDが違っても表示する(「別のSSID宛て」と表示)。SSIDまで一致し番号付きなら、Ackを返す(`:相手      :ackNN`)。Ackを返すかは自動送信の設定に従う(オフ=返さない、Ackのみ/間隔/フレックス=返す)
  - 同じ局・同じ番号(番号がなければ10分以内の同じ本文)の送り直しは1件にまとめ、Ackだけ返し直す
  - 一斉通知(宛先が `BLN…`): 表示する(未読には数えない)。同じ内容は1件にまとめる
  - 返信Ack形式 `{MM}AA` の AA は、送ったメッセージのAckとして扱う
  - 本文は表示できるASCIIだけ。それ以外(日本語など)は `?`
  - 新しい自分宛てメッセージ: 未読にし、ヘッダーに封筒のアイコン、画面下に「メッセージ受信: 局」を一時表示、受信音「ピピピッ」(4.4.1)
- 送信: 番号(1〜999、起動ごとに違うところから)を付けて送る。Ackが来るまで MSG_RETRY_INTERVALS_S(30秒→1分→2分→4分→8分)の間隔で最大5回送り直し、最後から MSG_FINAL_WAIT_MS(60秒)待って来なければ「応答なし」。Rejなら「拒否」。送り直しは自動送信の設定に関係なく行う(ユーザーが送ると決めたもの)
- 送信・Ackの返送は、他局の送信中なら止むまで待つ。MSG_BUSY_WAIT_MS(30秒)待っても止まなければ、その回は見送る(Ackは捨てる、メッセージは1回分として数える)。ビーコンより先に処理する
- 局とデジパスは、位置の送信と同じ設定(SSID、デジパス)を使う
- 保持: 受信・送信・一斉通知の合計 MSG_STORE_COUNT(20)件。超えたら古いものから消す(送り直し中のものは残す)。microSDに保存し、再起動後も残る(4.7.1)
- メッセージ画面: 一覧は新しい順に1件2行(「受」「送」「通」、時刻、相手、状態/未読、本文)。B短押しで詳細。詳細ではA/Cで前後(先頭は「新しいメッセージを作成」)、B短押しで 作成/返信/もう一度送る、B長押しで一覧へ。詳細を表示すると既読
- メッセージ作成: 宛先 → 本文 → 確認 の3段階。A/C=選ぶ、B=決定(確認ではB=送信)、B長押し=1つ戻る(宛先で戻ると作成をやめる)。作成中はA長押し(送信)・C長押し(メニュー)は使わない
  - 宛先の候補: キーボードで入力中の宛先、返信の相手、config.txt の friend1〜8、受信一覧の局(新しい順)。重複は出さない
  - 本文の候補: キーボードで入力中の本文、config.txt の定型文(msg1〜8)
  - キーボード(CardKB2)からも入力できる: 宛先は英数字と `-`(大文字にする、最大9文字)、本文は表示できるASCII(`|` `~` `{` は `?`、最大67文字)を入力できる。Enter=決定/送信、BS=1文字消す、Esc=戻る。確認画面では、定型文に書き足せる。キーボードがなくても、ボタンだけで作成できる
  - キーボードは30msごとに、I2C 50kHz(CARDKB_I2C_FREQ)で読む(実機で、100kHzでは入力が途切れることがあった)。接続の検知はせず、読めないとき(つながっていない・一時的な失敗)は何もしない。画面や動作はキーボードの有無で変えない
- 動作ログ: `msg_rx`、`msg_acked` / `msg_rejected`、`msg_queued`、`msg_tx` / `msg_ack`(送信)、`msg_failed`、`tx_skip msg_channel_busy`。シリアル診断: `MSG from …`、`MSG TX to … (回数)`、`MSG ack|rej from …`

## 5. 制約・非機能要件
- 開発環境: Arduino IDE。ライブラリは、OSSのライセンスで使えるものであれば制限しない(M5Unifiedなど)
- M5Unifiedのスピーカー・マイク機能は、DAC出力(GPIO25/26)と競合するため使わない(初期化でOFFにする)
- PC上のテスト: 計算部分(AFSK送受信、パケット、NMEA、設定、位置の取得元、ログ、画面の組み立て)は、ESP32なしでテストする。実機のタイミング、DAC/ADCの特性、外付け回路は、実機で確認する
- 割り込みの中では、処理時間の長い関数(SD、Preferences、画面描画、printfなど)を呼ばない
- ESP32のArduinoコアのバージョン: 2.1.4。コアの2.x系のAPIを使い、3.x系で変わったAPI(タイマ、I2S、ADCなど)は使わない
- アマチュア無線の免許と運用ルールの範囲で使用する

## 7. エラー処理・境界条件
- GPS未測位: 送信しない。画面に警告を表示
- GPSの通信が途絶えた場合: 画面に「GPS受信なし」と表示する。最終測位から5分以内は、最終測位位置で送信できる。それ以降は送信しない(4.1)
- 位置の取得元の位置が使えない(GPS未測位、保存位置なし、固定位置が未設定): 送信しない。他の取得元へは自動で切り替えない。画面に理由を表示
- PTTが10秒を超えた: 送信を中止してPTTを強制オフにし、受信に戻る(4.3)
- 受信: FCS不一致、情報フィールドが短すぎる(Mic-Eは9バイト未満)、未対応形式は、捨てて受信を続ける
- 受信バッファがあふれたとき:
  - サンプルのリングバッファ(割り込み → 復調): 割り込みは待たせたり止めたりしない。あふれたら新しいサンプルを捨てて(読み終わっていない古いサンプルを壊さないため)、途中まで復調していたフレームは破棄して、フラグ検出からやり直す。あふれた回数を数え、動作ログに記録する(書き込みは割り込みの外)
  - 受信パケットの待ち行列(復調 → 画面とSD): RX_PACKET_QUEUE_COUNT 件。満杯のときは、新しく受信したパケットを破棄し、破棄した件数を動作ログに記録する。受信と復調は止めない
